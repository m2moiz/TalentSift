## Key Findings

### HIGH severity (will cause implementation failure if not addressed):

1. **F12 — Phase 2-4 frontend seams are completely unspecified.** The plan defines 15+ backend endpoints for integrity/verification features but zero frontend hooks or UI components that call them. Each task needs an explicit frontend consumer: "Task 13 creates `useHiddenTextCheck(cv_file_id)` that calls `POST /api/analyze/hidden-text` and renders `<IntegrityBadge>` in `CandidateCard`."

2. **O18 — EUR-Lex uses SPARQL, not REST.** The plan treats all external APIs as REST (base_url + HTTP GET) but EUR-Lex is a SPARQL endpoint. Writing programmatic SPARQL queries is materially different from REST calls. The plan needs a SPARQL query template and a Python library (`SPARQLWrapper` or `httpx` with SPARQL protocol).

3. **C2 — `MOCK_MODE` env var naming conflict.** Vite only exposes `VITE_*` to the frontend. The plan says "Single env var MOCK_MODE across frontend and backend" but the frontend reads `VITE_MOCK_MODE` and the backend reads `MOCK_MODE`. Resolution: either document them as two vars or route through `/api/health`.

4. **X7 — `.omo/` is gitignored, making the plan's commit strategy non-functional.** The plan describes detailed commit workflows but the plan itself is outside version control.

### MEDIUM severity (will cause friction or bugs):

5. **B4 — `op_history_text` field missing from existing TS `NeedFormInput`.** Contract mismatch between plan Pydantic and existing code.
6. **B7 — `CvEntry` → `CvEntryForMatching` migration path undocumented.**
7. **F3 — Login body format (form-encoded vs JSON) not specified for the frontend.**
8. **O7 — `Andy8647/pdf-injection-scanner` is an unverified repo reference, no import path specified.**
9. **W3 — Task 22 missing from worktree merge list despite being V1-scoped.**
10. **X5 — File expiry (1h) can break integrity scans if delayed.**

### LOW severity (documentation/consistency improvements):

11. **B3 — `TokenResponse` split-delivery contract documented in prose but not Pydantic.**
12. **B5/B11 — `raw_ai_response` field inclusion in frontend types not clarified.**
13. **C11 — `VITE_OPENAI_MODEL` exists in SPEC but removed from plan without migration note.**
14. **X3 — Browser-direct API key calls not explicitly flagged for removal.**
15. **D6 — 2G backend memory may be tight for concurrent RoBERTa + Python runtime.**
